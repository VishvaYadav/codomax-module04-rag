sources**, and says *"I couldn't find this"* instead of making things up.

```
📄 Document → ✂️ Chunking → 🔢 Embeddings → 🗄️ Vector DB → 🔎 Retrieval → 🤖 LLM → 💬 Answer + sources
```

## ✨ App features

| Feature | Details |
|---|---|
| 📄 Document loading | PDF (with page numbers), TXT, Markdown; up to 5 files, or a built-in sample document |
| ✂️ Smart chunking | Sentence- and heading-aware, with adjustable chunk size and overlap |
| 🔢 Embeddings | Gemini embedding model, batched, with separate `RETRIEVAL_DOCUMENT` / `RETRIEVAL_QUERY` task types |
| 🗄️ Vector store | NumPy cosine-similarity index (`VectorStore` in `rag.py`) |
| 🔎 Retrieval | Top-k, minimum-similarity threshold, **MMR** for diverse results, follow-up-aware queries |
| 🤖 Grounded answers | Strict prompt: use only the context, cite `[1] [2]`, admit when the answer isn't there |
| 📚 Source viewer | Every answer shows the retrieved chunks, page numbers and similarity scores |
| 🧪 Hallucination check | Optional side-by-side answer **without** documents |
| 🛡️ Robustness | Live model detection, 60 s timeout, retries on 429/5xx, friendly errors with technical details |

## 🧠 Key concepts I learned

- **Hallucination:** the LLM fills knowledge gaps with confident guesses. It can't know private or new documents.
- **RAG:** retrieve the relevant parts of your documents first, then let the LLM answer from them.
- **Embedding:** a vector of numbers that represents meaning. Similar meanings point in similar directions (cosine similarity).
- **Chunking:** documents are split into small pieces so the right piece can be found. Size and overlap affect quality.
- **Vector database:** stores embeddings and finds the nearest ones fast (ChromaDB, FAISS, Pinecone …).
- **Retrieval evaluation:** hit rate@k and MRR show whether the right chunk is found before the LLM ever sees it.
